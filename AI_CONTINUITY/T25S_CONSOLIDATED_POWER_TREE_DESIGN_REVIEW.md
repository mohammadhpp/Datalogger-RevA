## Engineering route from this point

1. **Stop speculative model hunting and repeated identical scripts.** T25A's requested power-tree/model audit is complete. The vendor ZIP HTTP 403 is an access limitation; its absence does not undo earlier datasheet arithmetic. No substitute switching model or fabricated C(V)/load profile is authorized.
2. **For a prototype or when exact input evidence arrives:** establish actual OLED carrier 3.3 V rating and mating, firmware source/load operating sequence, selected card/current during power-up and write, AA voltage/sag under the intended loads and USB cable/OVP behavior. Obtain exact bias-dependent MLCC effective capacitance via qualified vendor data or direct characterization. These are *inputs*, not reasons to restudy unchanged schematic topology.
3. **Validate the real integration:** with a suitably validated long-timescale model **or instrumented prototype**, capture `BAT_SW` and `USB_VBUS_PROT`, `VIN_MUX`, `3V3_SYS`, `SD_VDD`, `OLED_VDD`, converter inductor current and branch/source currents as applicable. Test battery-only and USB-only cold start, USB↔battery transfer, SD/OLED enable separately and together, card write and display activity. Establish allowed voltage/time criteria from the *selected devices and firmware use*, then compare traces. A model showing averages does not qualify switching limits/ripple; bench evidence is a valid alternate final route when encrypted long startup is impractical.
4. **Design changes only when an actual failed limit is demonstrated.** If passive/source/load or waveform evidence misses a documented criterion, propose the minimal schematic change and then run compile/ECO, relevant PCB/DRC and the Git continuity checkpoint. Until then no component substitution, wrong-photo OLED pin swap or purported integrated PASS.
